# 햄스터봇 주행 수행평가 웹 앱

학생이 엔트리에서 미션을 수행하고, 실험 기록과 프로젝트 파일을 제출하면 교사가 진행 상황과 결과를 확인하는 앱입니다.

현재는 **수업 흐름을 검토하기 위한 브라우저 데모**입니다. 실제 학생 개인정보와 공식 평가 기록을 입력하지 마세요. 로그인·입장 토큰·Firebase 서버 저장·다른 기기 간 공유·파일 형식 검증은 아직 구현하지 않았습니다. 교사 전환 버튼은 체험용이며 접근 제어가 아닙니다.

## 실행

Node.js 22.12 이상(현재 검증: Node.js 24), npm을 사용합니다.

```sh
npm ci
npm run dev
```

## 체험 순서

1. `교사 대시보드`에서 **시험 시작**을 누릅니다.
2. `학생 미션`으로 돌아와 준비 항목을 체크하고 **준비 완료**를 누릅니다.
3. 다섯 미션에서 **미션 시작하기 → 자기 점검·실험 기록 → 미션 완료 요청**을 진행합니다.
4. `.ent` 파일을 선택하고 **선생님께 최종 제출**을 누릅니다.
5. 교사 화면에서 알림과 진행률을 확인하고 파일을 내려받거나 판정을 남깁니다.
6. 재시도는 교사 상세 화면에서 허용합니다. 이전 제출 파일과 시도는 유지됩니다.

체험 학생은 12명입니다. 상단 선택기로 학생을 바꿀 수 있습니다. 기록과 파일은 IndexedDB에 저장되어 새로고침 후 유지됩니다. 같은 브라우저의 동일 주소 탭 간에는 BroadcastChannel로 갱신됩니다. **다른 기기·다른 브라우저로 전송되지 않습니다.** 하단의 체험 기록 초기화로 파일까지 삭제할 수 있습니다.

엔트리 파일은 데모에서 확장자·크기(20 MiB)만 검사합니다. 실제 파일 규격과 안전성 검증은 하지 않으며 웹에서 실행하지 않습니다. 파일을 선택하는 것과 최종 제출하는 것은 다릅니다.

## 검증

```sh
npm test
npm run build
# Playwright 브라우저가 설치된 환경
npx playwright install chromium
npm run test:e2e
# 시스템 Chromium을 사용하는 경우
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

- 단위 테스트: 시험 상태, 자기 점검, 제출 조건, 중복 명령, 재시도 이력, 교사 판정 분리.
- 브라우저 테스트: 미션 5개 완료부터 파일 제출·다른 탭 알림·교사 검토·다운로드·새로고침과 모바일 화면.
- 실제 로봇 주행과 엔트리 블록은 검증하지 않았습니다.

## 구현 구조

- `src/missions.js`: 미션 콘텐츠와 설명용 의사코드.
- `src/model.js`: 상태 전이와 제출 조건. 데모용이며 보안 경계가 아닙니다.
- `src/store.js`: 브라우저 저장과 탭 간 갱신. 상태와 파일은 하나의 IndexedDB 트랜잭션으로 저장합니다.
- `src/main.js`, `src/style.css`: 학생·교사 화면.
- [spec.md](spec.md): Firebase 기반 운영 버전 설계와 현재 구현 범위.

## Firebase 운영 연결 전 필요한 작업

사용할 프로젝트는 `hamster-ea443`입니다. 웹 앱 설정만으로 DB·인증·보안 규칙이 구성되지는 않습니다. 현재 앱은 Firebase에 연결하거나 어떤 데이터도 전송하지 않습니다. 다음은 실제 수업 사용 전에 별도로 구현·검증해야 합니다.

- Authentication의 교사 로그인·학생 입장 및 명단 연결.
- Cloud Firestore 컬렉션과 Security Rules, 권한 검사와 상태 전이를 수행하는 Callable Functions.
- Cloud Storage 파일 업로드·검증·접근 규칙과 제출 확정 처리.
- 다른 기기 간 실시간 진행률·지속 알림, 판정 수정 충돌 처리, 보관 만료 삭제.
- 학교 계정·개인정보·보관 정책, 엔트리 파일 규격 및 손동작 기능 확인.

서비스 계정 비밀 키를 프런트엔드에 넣지 않습니다. 운영 배포나 환경 게시는 수행하지 않았습니다.
